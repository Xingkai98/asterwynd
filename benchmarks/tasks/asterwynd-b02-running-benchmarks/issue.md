# 新增只读工具：列出 benchmark 评测轮次

评测闭环会按轮次把运行结果落到一个输出目录：每一轮次一个子目录，子目录名即 `run_id`。已完成的轮次子目录内含 `run.json` 元数据（含 `status`、`passed`、`task_count` 字段）；尚在运行、还没落元数据的轮次子目录只有目录、没有该文件。

Agent 在开发过程中经常需要知道「当前有哪些评测轮次、各自进行到哪一步」，但目前没有任何内置工具能直接回答——只能靠手动翻目录读文件拼出信息。

## Task

新增一个只读工具 `ListRunningBenchmarks`，让 agent 一次调用即可列出评测输出目录中的所有轮次：

- 遍历评测输出目录下的子目录，每个子目录即一轮次
- 已完成的轮次输出 `<run_id> | <status> | <passed>/<task_count>`（`task_count` 是任务总数；`status` 取 `run.json` 的 `status` 字段）
- 尚无元数据文件的子目录输出 `<run_id> | in_progress`
- 输出目录不存在或为空时返回明确的空占位文本
- 工具无参数，构造时可注入输出目录（默认评测输出目录）

该工具必须走完整装配链，成为 agent 运行时真正可调用的内置工具（而不是一个孤立的类）：实现文件 → 工具工厂的两个装配入口 → 运行时注册表 schema 面。参照既有只读工具（如列目录工具）的命名与权限约定：工具名 `ListRunningBenchmarks`、实现类名 `ListRunningBenchmarksTool`、只读权限。注意：装配后还需把工具名登记进「已知内置工具名」清单，否则装配期校验会报未知工具。

## Requirements

- 工具工厂两个装配入口构造的注册表都包含 `ListRunningBenchmarks`
- 经注册表 schema 面可见、`execute()` 可调用，输出符合上述行格式
- 空目录 / 不存在的目录返回空占位文本
- 既有工具装配测试与注册表测试不得回归
