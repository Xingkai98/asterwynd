# 结果页按 track（A/B/verified）分组

任务集由三来源组成：A 轨（历史重建回归基线）、B 轨（当前 HEAD 演进）、verified（SWE-bench 精选子集），每个任务在任务清单里有 `track` 字段标记归属。评测结果页目前按「能力层」和「任务」两个维度聚合，**缺少按 track 的分组视图**——混跑三来源后，无法一眼看出「每个轨的整体表现（任务数 + 通过率）」。

## Task

让评测结果页新增按 track 分组的聚合块：

- 分组键为任务清单里的 `track`（A/B/verified）
- 每组展示任务数与 Pass@k（该组全部有效轮次的通过率，口径与既有块一致）
- 对历史产物（结果文件里没有 track 字段）需有兜底推断：任务 id 以 `swebench-` 开头 → verified、`asterwynd-b` 开头 → B、其余 → A
- 无分组数据（空聚合）时不渲染该块

这需要打通整条数据链：任务结果数据模型要能携带 `track` 字段 → 评测执行器在产出结果时从任务清单填入该字段 → 聚合层把 `track` 归一化到分组 → 渲染层（markdown 与 HTML 两套）输出分组表。历史产物没有该字段时靠上面的 id 前缀兜底，不能因缺字段而崩溃。

## Requirements

- 结果页（markdown 与 HTML）含按 track 分组块：`| Track | Tasks | Pass@k |`
- 分组合计正确：A/B/verified 各一组，组内任务数与通过率与逐任务明细一致
- 结果数据模型新增 `track` 字段；执行器构造结果时从任务清单填入
- 历史产物（无 track 字段）能正常渲染分组（id 前缀兜底）
- 既有结果页渲染测试不得回归
