# 长期记忆按项目 scope 隔离

长期记忆系统按「项目」分 scope：每个项目（git 仓库根或解析后的项目根）有自己的记忆目录（`~/.asterwynd/projects/<project-hash>/memory/`），不同项目不共享记忆文件。但当前有两个缺口：

1. **写入工具**：保存记忆的工具没有 `project` 参数——agent 无法显式把一条记忆写进指定项目（只能写进当前工作区默认项目）。
2. **上下文注入源**：把记忆摘要渲染进上下文的注入源没有按项目绑定——它只从默认项目读，无法「按当前会话项目过滤注入」。

导致：跨项目切换后，A 项目写的记忆仍可能从默认注入面可见（或反之读不到），scope 隔离不闭合。

## Task

打通「写入端 + 注入端」的双端闭合隔离：

- **写入端**：保存记忆工具新增 `project` 参数（可选）。显式给定时，该条记忆写入指定 project hash 的记忆目录；不给定时维持写当前项目。
- **存储层**：记忆存储支持以显式 project hash 构造（覆盖默认从项目根推导），并提供「派生同配置、绑定另一 project」的方法，供写入端与注入端复用同一构造路径。
- **注入端**：记忆摘要注入源可绑定一个 project hash，渲染时只从该 project 的记忆目录读摘要；不绑定时维持默认行为。

判定标准：构造两个项目 A/B 的记忆存储实例 → 写一条记忆到 A → 绑定 B 的注入源渲染时不可见（无摘要）→ 绑定 A 的注入源渲染时可见（可复用）。

## Requirements

- 保存记忆工具接受 `project` 参数并写入对应 project 存储
- 存储层支持显式 project hash 构造与同配置派生
- 注入源按 project 过滤：绑定 B 看不到 A 的记忆，绑定 A 能看到
- 既有记忆工具 / 注入源 / 上下文构建测试不得回归
