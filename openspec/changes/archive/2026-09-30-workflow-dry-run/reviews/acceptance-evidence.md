### S6（端到端有效性）= **1/3**

**run 1 完成**：最终图含全部要素（`w1..w4` 扇出 → `synth` 扇入 → `gate`(route) → **`gate→w1/w2/w3/w4` 定向回边** → `final` 聚合），产出 `analysis/verdict.md`。

**run 2/3 超时**——但**不是卡在工具语义上**：
- run 2 起了 **104 次 `read_only` 子 agent 分析**（+54 次 bypass run）；
- run 3 起了 **27 次 `read_only` 分析**（+33 次 bypass run，86 次 LLM HTTP 调用）。

**归因**：模型把预算花在**做任务**上（真实的多维度分析），而不是像 #248 那样花在**逆向工程工具**上。任务本身（4 路并行分析 + 评审 + 回炉 + 聚合）在这套 token 预算下就是重活。**但墙钟 2400s 确实是跑不完的**——这是如实的未达标，不粉饰。

### S7（负面检查：是否形成新的试探循环）= **未形成** ✅

`DryRunWorkflow` 调用 **8 / 18 / 9**，全部**远低于硬上限 40**。**run 1 完全没有触发软提醒。**

**一处需记录的观察**：run 2 在 **8 秒内对同一张 9 节点图连 dry run 3 次**（`21:55:43 / :47 / :51`），每次微调 `reducer` 配置。这**不是**失控循环（3 次后即收敛并转入真实执行），但说明「反复 dry run 调图」是**真实会发生的模式**——Q5 的软提醒（~10 次）阈值选得合理。

### S8（dry run 是否替代了探针）= **是** ✅ —— 本 change 的核心假设成立

`DryRunWorkflow` 的 goal 分类（以 run 1 为例）：

| goal | 次数 | 性质 |
|---|---|---|
| 业务目标本身（「4 并行 worker…最终聚合」） | 2 | **对着真正要用的图 dry run** |
| `test feedback injection` / `v2` | 2 | 语义验证（旧世界的「探针」） |
| `test bus channel` | 2 | 语义验证 |
| `full topology check` | 1 | 语义验证 |
| `final input check` | 1 | 语义验证 |

**5 次是语义探针，但形态从「烧真 token 的一次性真图」变成了「零 token 的模拟」。** 这正是设计意图。

**决定性证据——模型自发用 `script` 数组表达循环收敛**（run 1 首次调用，**未被告知用法**）：

```python
script = {
  'synth': ['VERDICT: REDO\n维度B证据不足，回炉。', 'VERDICT: DONE\n四维度齐备。'],
  'w2':    ['维度B初版（定性）', '维度B重做版（含量化证据）']
}
```

**这是 Q1 决策（数组按调用次序消费）的教科书式落地。** run 2 同样自发使用（`'agg2': ['VERDICT: READY…', 'VERDICT: NEEDS_WORK…']`）。

**且它当场赚回成本**：run 1 同一次 dry run 返回
```
invalid_spec: node 'synth' slot 'result' is written by multiple upstreams
              ['w1','w2','w3','w4'] but [...] declare no reducer
```
**零 token 抓到一个真实 spec 缺陷**——在 #248 的世界里这要靠起真图撞错。

### 软判断（主 session）

- **理解工具**：run 1 **第一次调用就用对了 `script` 数组**（含按轮次收敛意图），没有出现 #248 那种「写 20 张图逆向工程 DSL」的行为。`notes` 的「答不了清单」也起了作用——模型没把占位产出当真实结论。
- **理解任务**：run 1 的产出有实际分析深度（含「w4 上轮自相矛盾已修正」这类跨轮修正）；run 2/3 起了 104/27 次真实子 agent 分析。**时间花在任务上，不是花在工具上。**

## 诚实记录的问题

1. **S6 = 1/3 未达标**：run 2/3 被墙钟截断。若要把它们跑完，需要更大的 wall-clock 预算（或更小的任务）。**这不改变 S0 的结论**（探针归零是在超时前就已成立的），但**「任务能否在预算内跑完」这件事本 change 没有解决**——它可能属 #269 的范畴。
2. **`graph_recursion_exceeded` 仍出现**（run 2: 11 次；run 3: 2 次）——说明模型写的图**更复杂了**（run 2 是 17 节点图），撞上限的概率随之上升。**这恰恰说明 dry run 让模型敢于写更复杂的图**，是收益也是新压力。
3. **token 仍超预算**（run 1 TokenBudget 报 295%）。**不设 token 降幅门槛**（#248 教训：收益形态是「消除一整类无效动作」，不是线性省 token）。
